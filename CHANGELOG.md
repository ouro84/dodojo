# Changelog

Toutes les features notables (produit et technique) de "Boss de la Journée" sont documentées ici.

Format des versions : `XX.YY.ZZ` (Majeure.Mineure.Fix), aligné sur les releases GitHub.
Chaque feature livrée est ajoutée sous `[Unreleased]` dans le même commit/PR que son
implémentation ; à chaque release GitHub, le contenu d'`[Unreleased]` bascule dans une
nouvelle section versionnée et datée.

### Technique
- Intégration de graphify (graphe de connaissances du dépôt) : section `## graphify` ajoutée à `CLAUDE.md` (requêter le graphe via `graphify query`/`path`/`explain` avant grep/browsing brut, `graphify update .` après modif de code) + hooks `PreToolUse` locaux (`.claude/settings.json`, gitignoré) qui rappellent le graphe avant Bash/Read/Glob. `graphify-out/` (sortie générée, régénérable) ajouté au `.gitignore` — pas une source de vérité versionnée.
- CI (`.github/workflows/ci.yml`) rouge sur `main` depuis le 2026-07-27 sur tout run : `node-version: 20` restait pinné alors que plusieurs dépendances (`@supabase/*@2.110.7`, `@testing-library/jest-dom@7.0.0`) exigent désormais Node ≥22 — l'écart de version npm (10.8.2 sous Node 20 vs 11.x sous Node 24 en local) faisait diverger la résolution de `package-lock.json`, `npm ci` échouant en `EUSAGE` (« Missing: @swc/helpers@0.5.23 from lock file ») avant même d'atteindre lint/tests. Aligné sur Node 24 (déjà la version de prod Vercel) dans les deux jobs (`checks`/`e2e`) + `engines.node >=22.0.0` ajouté à `package.json` pour éviter la régression silencieuse. A aussi révélé une cascade de problèmes restés invisibles tant que `checks` échouait en premier, le job `e2e` n'ayant donc jamais réellement exécuté un test depuis la mise en place des secrets (2026-07-20) : `NEXT_PRIVATE_KEY_SUPABASE` (clé service-role) puis `E2E_ONBOARDING_EMAIL`/`E2E_ONBOARDING_PASSWORD` (compte dédié `onboarding.spec.ts`) manquaient à la fois dans `ci.yml` et dans les secrets du repo — les trois sont désormais référencés et renseignés.
- `webServer.timeout` de Playwright relevé de 240s à 600s (non conditionné à `CI` : c'est un plafond d'attente, pas un délai payé, et le côté lent est le poste local — 29s mesurées en CI pour prebuild + build + start + globalSetup, contre plusieurs minutes sur un poste Windows). Le dépassement était piégeux : le `npm run build` tué à mi-parcours laissait `.next` incomplet et le run *suivant* échouait sur « Could not find a production build », loin de la vraie cause. Complété par un `timeout-minutes` sur les deux jobs CI (15 pour `checks`, 45 pour `e2e`, au lieu du défaut GitHub de 360) pour borner le coût d'un job bloqué — les crédits Actions du repo ont déjà été épuisés une fois. Corrige au passage un commentaire de `ci.yml` qui annonçait `npm run dev` alors que le `webServer` démarre un serveur de production.
- Suite e2e verte en CI (issue #156) : trois causes distinctes, toutes invisibles en local. (1) `playwright.config.ts` ne posait que `timeout` (budget par test) et laissait les assertions au défaut de 5s — insuffisant pour celles qui suivent une server action lente (`closeDay` mesuré à 5 853 ms depuis un runner GitHub, ≥10 aller-retours Supabase séquentiels), d'où l'échec déterministe de `journey-full-day.spec.ts` ; `expect.timeout` passe à 15s en CI. (2) `journey-full-day.spec.ts` détectait l'overlay K.O. par un `count()` immédiat alors qu'il n'apparaît que ~2,4s après le coup fatal et recouvre désormais tout l'écran — il est soldé via `dismissKoOverlayIfPresent` avant la clôture. (3) `ko-overlay-viewport.spec.ts` bornait sa boucle de mise à mort à 20 tours, dépassé depuis longtemps par l'accumulation de tâches sur le compte e2e partagé (RG-04) : le Boss restait debout et l'overlay n'apparaissait jamais — la boucle sort désormais sur les HP du Boss. `combat-animations.spec.ts` n'échantillonne plus un état d'anim de 350 ms au poll de `expect` (dont l'intervalle recule jusqu'à 1s) mais enregistre la suite des transitions frame par frame, ce qui rend au passage le « jamais attack » du test une assertion réelle et non plus déduite.
- Issue #114 (fondation) : migration du cron push de GitHub Actions (échec 100% en prod, jamais fonctionnel) vers Inngest — cron statique `reminder-fanout` (`*/15 * * * *`) + fonction `send-reminder` par profil éligible, déterminisme garanti (valeurs figées dans l'event), observabilité `onFailure`.
- Issue #101 : 4 specs e2e Playwright (`hero-bar-tooltip`, `hero-heal-float`, `deadline-missed-chip`, `overdue-rest-chip`) + helper `seedMissedDeadlineTask` (`e2e/fixtures.ts`) pour court-circuiter le polling ~45s. Tests unitaires Vitest `deferredRestHpPenalties` (6 cas) dans `lib/game-engine.test.ts`.
